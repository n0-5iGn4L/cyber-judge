01 / 问题

热点不缺观点，缺的是可核对的观点。

大多数“分析”会长成三种样子：复述新闻、罗列双方、最后落在“仍需观察”。读者读完，还是不知道哪句话更站得住。这里的做法是把一场争议拆成可审理的争点，逐条评价具体主张，给出支持度与理由，最后落到一个明确的当前判断。

维度常见做法赛博判官
结论各有各的道理，等待后续。当前最佳解释，并写明什么材料会改变判断。
评价单位整个事件，或整个人。一句具体主张：谁说、说了什么、支持到哪一步。
支持度语气、立场、看起来像。六类语义标签，每一类都带理由，不折算成百分比。
出处文末一堆链接。每段可点回证据条目，再从条目回到对应争点。
可修正不说明什么会推翻它。指明决定性材料；新证据出现就改判。
02 / 方法

一场审理，五步走完。

流程写在技能入口里，报告结构由模板承载。换一个事件，换的是数据，不是版式。

  1. 01

    立案与分流

    确认对象、时间、触发材料与本次主问题。事件争议与公共议题走两条轻量分支；有实质歧义才作最小澄清。

  2. 02

    证据台账

    记下谁说了什么、何时说的、读到的是正文还是元数据、缺口在哪里。不同转载不按独立证据累计。

  3. 03

    争点审理

    每个争点四拍：问题、各方主张、证据与支持度、局部裁定。同一方可以在不同争点上得到不同评价。

  4. 04

    收束

    哪些说法站得住、最佳解释是什么、哪几个问题真正未决。不用“各有道理”代替结论。

  5. 05

    交付

    单文件 HTML：目录、页边批注、证据回链、判词卡、打印样式。双击可读，不请求任何外部资源。

03 / 方法的一个切面

不给百分比，给能被反驳的理由。

支持度只评价某一句话，不评价人，也不折算成总分。六个标签对应六种形状，读者不必靠颜色分辨。

  • 支持较强直接材料与主张相符，关键反证不足以推翻。
  • 支持有限部分材料相符，关键连接仍依赖推断或来源单一。
  • 支持不足提出了说法，但没有支撑它的关键证据。
  • 有明确反证可核对材料与主张直接冲突。
  • 暂无法判断缺少决定性材料，现有解释难以区分。
  • 规范判断评价原则类主张，不按事实支持度计。

没有“87% 可信”，没有阵营血条，没有人物总分。一场争论也不一定只有两方：三种以上立场、同为一方却在不同争点上评价不同，都是正常结果。

05 / 阅读

长文，但不用硬读。

首屏先给判断，正文按争点跳读，证据从任何一句判断一步可达。默认展示背景与核心论证，方法说明放附录。

  1. 01

    30 秒首屏

    案由、追问、核心判断、截至日期。免责话不占第一屏，限定只跟着它影响的结论。

  2. 02

    页边批注

    支持度与理由和主张同一行对齐；手机落到主张下方，带一条竖线，不丢层级。

  3. 03

    证据回链

    正文的 V1 → 证据条目 → “被引用于 §争点 01”。从判断到出处，再回到读到的位置。

  4. 04

    判词卡

    事件名、四项裁定、截至日期、证据编号。截图可分享，被裁掉的只有完整推理。

07 / 开始

三步，从事件到报告。

技能入口是 SKILL.md，写作与分支规范在 references/，渲染入口是 template/build.mjs。Node 18 以上，零第三方依赖。

  1. 01

    放进 skills 目录

    把 skill 目录放到你的 Agent 技能路径，SKILL.md 是入口。

  2. 02

    写这一期的数据

    复制一个报告对象，替换标题、争点、主张与来源编号。

  3. 03

    渲染并校验

    一条命令输出 HTML；校验会拦下不存在的来源编号、非法链接与空字段。

# 渲染全部报告
$ node template/build.mjs

# 只做校验，不写文件
$ node template/build.mjs --check
校验通过：2 份报告，0 条提示。

# 只渲染一份
$ node template/build.mjs v800

构建时内联 CSS 与脚本；成品不请求字体、框架或数据。

08 / 边界

说清楚什么还没验证。

  • 两案都是事件争议分支；公共议题分支还没有样例验证，不为展示分类硬改案例。
  • 材料截至 2026-10-19；结论会随新证据改判，这是设计的一部分，不是补丁。
  • 它是分析工具，不是司法裁判，也不替代专业鉴定或法律意见。
  • 报告与模板都是静态文件：没有后台、没有账号、不上传数据。
